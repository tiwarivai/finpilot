# FinPilot - Project Problem Statement

## 1. Client Background
NorthStar Financial Services is a financial services organization that manages customer, account, transaction and payment-related data across multiple business applications.

The organization currently operates a combination of legacy and modern applications supporting core financial operations, reporting and customer services.

As part of its technology modernization strategy, NorthStar is transitioning selected legacy data and workloads to a cloud-based platform. The transformation requires reliable data migration, validation, reconciliation, governance, security and operational visibility to ensure that business operations remain accurate and traceable throughout the modernization lifecycle.

## 2. Current Environment
### 2.1 Existing Applications

NorthStar Financial Services currently operates multiple applications supporting customer management, account management, transactions, payments and reporting.

The current application landscape includes:

* Legacy Customer Management System — maintains customer profiles and identification-related information.
* Legacy Account Management System — maintains account details, account types, balances and account status.
* Transaction Processing System — records financial transactions such as deposits, withdrawals and transfers.
* Payment Processing System — manages payment instructions and payment processing status.
* Enterprise Reporting System — consumes data from multiple source systems for operational and management reporting.

The applications were developed and maintained at different points in time and use different data structures and interfaces.

### 2.2 Current Data Flow

Customer and account information originates in the respective legacy systems. Transaction and payment data is generated by operational applications and subsequently made available to downstream reporting systems.

The current high-level data flow is:

Customer Management System → Account Management System → Transaction Processing → Payment Processing → Enterprise Reporting

Data is transferred between systems through a combination of database extracts, scheduled file transfers and application interfaces.

The current flow has limited centralized visibility into data quality, transformation rules, validation results and end-to-end data lineage.

### 2.3 Current Integration Landscape

The legacy environment contains multiple integration mechanisms, including scheduled batch processes, database extracts, flat-file exchanges and application interfaces.

Different systems use different data formats, naming conventions and field structures. Integration failures are generally identified through application monitoring, operational alerts or manual investigation.

There is no single centralized platform that provides end-to-end visibility of integration status, failed records, validation results and reconciliation outcomes.

### 2.4 Current Data Validation Process

Data validation is currently performed using a combination of SQL queries, source-to-target comparisons, application reports and manual checks.

During migration or data-processing activities, analysts compare selected source and target records to identify missing records, incorrect values, duplicate records and transformation-related discrepancies.

The current validation process requires significant manual effort and does not provide a standardized centralized mechanism for recording validation rules, execution results, exceptions and evidence.

### 2.5 Current Reporting Process

Operational and management reports are generated from data collected from multiple source applications.

Reporting teams perform data extraction, transformation and reconciliation activities before producing reports for business stakeholders.

Because data originates from multiple systems, differences in data definitions, timing and transformation logic can result in reporting inconsistencies and additional reconciliation effort.

### 2.6 Current Access and Security Model

Access to applications and data is managed through application-level permissions and existing enterprise identity and access-management mechanisms.

However, access definitions are not consistently centralized across all data-processing and reporting activities. Visibility into who can access specific datasets, pipelines and operational information is limited.

The modernization initiative therefore requires a more structured role-based access-control model with clearly defined responsibilities and access levels.

### 2.7 Current Operational Challenges

The current environment presents several operational and data-management challenges:

* Multiple legacy applications with different data structures.
* Inconsistent data formats and business definitions.
* Manual data validation and reconciliation activities.
* Limited end-to-end data lineage.
* Difficulty identifying and investigating failed records.
* Limited centralized visibility into migration and data-quality status.
* Reporting inconsistencies caused by differences across source systems.
* Complex access management across applications and datasets.
* Increased operational effort during migration and modernization activities.
